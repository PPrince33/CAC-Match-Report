CAC Match Report — Event Hierarchy
====================================
Structure of every row in `processed_match_events`:

    Action  ──►  Outcome  ──►  Type

Action     = WHAT the player did
Outcome    = HOW it ended
Type       = additional qualifier / context

Below: every valid (Action, Outcome, Type) combination currently in CAC_LOGIC.
"NA" means the row has no further qualifier in that slot.

====================================================================
NOTES ON CONVENTIONS
====================================================================

Player roles per row
  • player_id            = the actor (defender, passer, shooter, etc.)
  • reaction_player_id   = the opposite end of the action
                            – Pass / Through Ball  → the receiver
                            – Tackle               → the player dispossessed
                            – Pass Intercept       → the passer whose ball was cut out
                            – Block                → the player whose shot/pass was blocked
                            – Save                 → the shooter
                            – Substitution         → the player coming ON
                            – Ball Control loss    → opponent that picked it up

Successful pass family
  ['Successful', 'Key Pass', 'Assist']
   → counted as completed passes everywhere (Pass Acc %, Passing Network, etc.)

Incomplete pass family
  ['Missed', 'Intercepted', 'Off-Side']
   → used for accuracy denominators in the Passes tab so the rate ignores
     non-classifiable outcomes

Successful defensive family
  Pass Intercept / Tackle / Block / Pressure  outcome === 'Successful'
  Save                                        outcome ∈ {Gripping, Pushing-in, Pushing-out}

Possession-regaining marker
  Successful + Type === 'With Possession'
   → counts toward "Regained Possession" / "Total Regained Possession"

Direction normalisation
  • team_direction          = direction stored in the processed row
                              (events are normalised so attacks always run L→R
                               when reading stats)
  • original_team_direction = the raw recording direction
  When team_direction !== original_team_direction the (start_x, start_y,
  end_x, end_y) tuple was flipped during processing. To draw events on the
  pitch in their actual real-world direction, mirror back with:
        x  →  pitch_width  − x         (120 football, 40 futsal)
        y  →  pitch_height − y         (80 football, 20 futsal)
